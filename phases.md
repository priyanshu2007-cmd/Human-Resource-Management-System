# phases.md — Dayflow build order

Status reflects actual current state, verified in-browser and via `tsc --noEmit`, not just "written."

- [x] **Phase 1 — Scaffold.** Next.js + Tailwind + shadcn/ui wired up with design tokens. Supabase client/server/admin helpers + session middleware in place.
- [x] **Phase 2 — Database migration.** All 6 tables (`organizations`, `profiles`, `salary_structures`, `documents`, `attendance`, `leave_requests`), helper functions (`my_organization_id`, `is_admin`, `generate_login_id`), bootstrap RPC (`create_organization_and_admin`), full RLS, storage buckets. Applied directly to the live project.
- [x] **Phase 3 — Auth & onboarding.** Sign-up (company + admin), sign-in (Login ID or email), forced password change on first login, role-based route protection in each section's layout.
- [x] **Phase 4 — Employee dashboard + profile.** Profile view/edit (phone/address/photo upload to Storage), dashboard quick-access cards.
- [x] **Phase 5 — Attendance.** Employee check-in/out + own history; admin org-wide table with summary stat row (Total/Present/Half-day/Absent-Leave).
- [x] **Phase 6 — Leave.** Employee apply flow; admin approval queue (card-based, approve/reject + comment) at `/admin/leave-approvals`.
- [x] **Phase 7 — Payroll.** Employee read-only view (current + history); admin insert-new-structure form (history preserved, never overwritten).
- [x] **Phase 8 — Admin employee management.** List (card grid), creation (generates Login ID + temp password, shown once), detail view + edit (job title/department/phone).
- [ ] **Phase 9 — Cross-role security pass.** RLS policies exist and were checked against each query at write-time, but there has been **no adversarial test** — e.g. actually attempting to read a second org's data with a real second account. Not yet done.
- [~] **Phase 10 — Polish.** Responsive layouts done per-screen as built (not a separate pass). Stitch visual alignment done for employee list/attendance/leave/sign-in. Not done: full loading/empty/error-state audit across every screen; the root `/` route was a leftover dev-scaffold page until this was caught and fixed (now redirects by role).

- [x] **Phase 11 — Dark/light mode.** Custom toggle (no next-themes dependency), `.dark` class + localStorage, blocking pre-paint script to avoid flash. Fixed a real bug: `--foreground` token was never defined, so `text-foreground` silently fell back to black — invisible in dark mode. Now fixed globally.
- [x] **Phase 12 — Holidays + leave calendar.** New `holidays` table (org-wide, admin-managed). Employee-facing month calendar at `/employee/calendar` coloring days by attendance/leave/holiday, with a worked-days summary. Admin holiday management at `/admin/holidays`.
- [x] **Phase 13 — Sign-up visual redesign.** Split-panel layout (violet gradient brand panel + form panel) matching a provided reference design. Zero change to underlying signup logic (RPC calls, validation, email-confirmation fallback) — pure JSX/layout restructure.
- [~] **Phase 14 — Major scope expansion (in progress).** A detailed new brief substantially expands the data model and reverses one earlier PRD exclusion. Specifically:
  - **Schema growth**: `profiles` gains DOB, address, nationality, gender, marital status, manager (self-referencing), location, and full bank/compliance fields (account number, bank name, IFSC, PAN, UAN). `leave_requests` gains an attachment (for sick-leave certificates). `salary_structures` gains a real auto-calculating model driven by a single "Month Wage" input (see design decision below).
  - **Dummy data seeding**: 10 fully-populated fictional employees, ~2 months of daily attendance, leave history (approved/rejected/pending across all 3 leave types), and computed salary records — so every screen has real-looking data on first load instead of empty states. This is synthetic seed data for local development, not real people's information.
  - **PRD exclusion reversed**: the payroll dashboard now explicitly requires bar-chart visualizations (total expenses / paid / remaining) — this directly contradicts the original PRD's "no analytics/reports dashboard" line. Treated as an intentional scope update per explicit instruction, not an oversight. `prd.md` needs updating to reflect this the next time it's touched.
  - **Still to build on top of the schema**: admin salary-config UI with live recalculation as Month Wage changes, payroll bar charts, employee tabbed profile (Resume/Private Info/Salary Info/Security), leave-request modal with attachment upload and auto-calculated day allocation, admin global attendance view with a date picker for any past day/month.
  - **Design decision on the salary formula**: the brief's stated percentages don't arithmetically reconcile (Basic + HRA + Standard + Bonus + LTA already sum to 100% of Month Wage before Fixed Allowance's stated 11.67% is added on top). Resolved by computing Fixed Allowance as the true mathematical remainder (Month Wage minus every other component), which guarantees gross pay always reconciles exactly — an explicit requirement in the original PRD ("ensure payroll accuracy... totals reconcile") — rather than forcing a percentage that would make the numbers not add up.

## Known gaps (see prd.md "explicitly out of scope" — note Phase 14 reverses the payroll-chart part of this)
- No leave balance/quota tracking — schema doesn't have it, employee leave page deliberately has no balance progress bars. (May need revisiting given Phase 14's leave-allocation auto-calc requirement.)
- No email confirmation currently enforced in the live Supabase project (toggled off during dev troubleshooting) — **revisit before any real deployment**, since the PRD's own sign-up flow assumes it.
